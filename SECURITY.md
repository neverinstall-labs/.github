# Security policy

This policy applies to every repository in the `neverinstall-labs` organisation that does not have its own
`SECURITY.md`.

## Reporting a vulnerability

Do not open a public issue for a security problem.

Report it privately by one of these methods:

1. **GitHub private vulnerability reporting.** On the repository page, open **Security** and select
   **Report a vulnerability**.
2. **Email** `security@neverinstall.com`.

Include:

- The repository and the version, tag or commit.
- A description of the problem and its impact.
- Steps to reproduce it, or a proof of concept.
- Whether the problem is already public.

## What happens next

1. We acknowledge the report within 3 business days.
2. We confirm or reject the problem and tell you our assessment.
3. We fix confirmed problems, publish a release and a GitHub security advisory, and credit you unless you ask us
   not to.

## Supported versions

Only the latest release of each tool receives security fixes.

## Scope

In scope: code, scripts, release artifacts and build pipelines in this organisation.

Out of scope: the Neverinstall products and services. Report problems with those to `security@neverinstall.com`
and say which product is affected.
